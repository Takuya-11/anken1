## ① 自己評価

### 技術面

**詰まったポイント**

| 問題 | 原因 | 解決策 |
|---|---|---|
| Node.js v26 で `npm run dev` が動かない | `.bin/` がシンボリックリンクではなくコピーになり相対パスが壊れる | `package.json` のスクリプトを `node node_modules/next/dist/bin/next ...` に変更 |
| Next.js 16 で `dynamic = 'force-dynamic'` がビルドエラー | v16 で `cacheComponents` と競合 | `export const instant = false` に変更 |
| `middleware.ts` がビルドエラー | v16 でファイル規約が変更 | `proxy.ts` にリネーム、関数名を `proxy` に変更 |
| ログインページがリダイレクトループ | admin layout がログインページにも適用された | route group `(dashboard)` でスコープを分離 |
| Claude が JSON をコードブロックで包んで返す | プロンプトに「JSONのみ返せ」と書いても無視される | `raw.replace(/^\`\`\`(?:json)?\s*/i, '')` で除去 |
| **temperature=0 追加でbotが完全停止** | TypeScript 型エラー回避のスプレッド構文が実行時に Anthropic SDK エラーを発生、`askClaude` が throw → `Promise.allSettled` が握りつぶし → LINE に返信なし・ログも出ない | temperature を削除し `askClaude` 全体を try-catch で囲む。型定義にないパラメータは `// @ts-ignore` か SDK アップデートで対処 |

**うまくいった工夫**
- **Few-shot 例 8件のプロンプト埋め込み**: API コスト増加ゼロで確信度精度を大幅改善。境界ケース（返金・予約確定・施術組合せ）を具体的に列挙したことが効いた
- **Server Actions + revalidatePath**: CRUD の実装がシンプルになり、楽観的 UI 不要で動作が安定した
- **`Promise.allSettled` でイベントを並列処理**: Webhook が複数イベントを受けても安全に処理できる

**次回試したい技術**
- Supabase Realtime で会話ログをリアルタイム更新
- Vercel AI SDK の `streamText` でレスポンスをストリーミング表示
- Anthropic prompt caching で繰り返しの FAQ 注入コストを削減

## ② 見積もり vs 実績

| フェーズ | 見積もり | 実績 | 誤差 |
|---|---|---|---|
| プロジェクトセットアップ | 0.5 人日 | 0.5 人日 | ± 0 |
| Supabase スキーマ + Auth | 0.5 人日 | 0.5 人日 | ± 0 |
| LINE Webhook + Claude 連携 | 1.0 人日 | 1.5 人日 | **+50%** |
| 管理画面（FAQ / メニュー） | 1.5 人日 | 1.0 人日 | -33% |
| 会話ログ + 一斉配信 | 1.0 人日 | 1.0 人日 | ± 0 |
| テスト・デバッグ | 0.5 人日 | 1.5 人日 | **+200%** |
| **合計** | **5.5 人日** | **6.5 人日** | **+18%** |

**誤差が大きかった原因**
- Webhook のデバッグに時間がかかった（温度パラメータ問題・ログが出ない問題）
  - `Promise.allSettled` がエラーを握りつぶすパターンは次回も踏みやすい → **Webhook には必ず独立した try-catch とログを最初から入れる**
- Next.js v16 特有の破壊的変更（`instant`, `proxy.ts`）への対応が見積もり外

## ③ 改善メモ（Chapter 3 以降に活かす）

### 次の案件でやること

1. **ヒアリングをもう 1 ラリー追加する**
   - 初回ヒアリング後に「想定されるエッジケース」を返す。今回は実機テストまで判明しなかった文言問題を事前に潰せる

2. **Webhook には最初から独立 try-catch とログを入れる**
   - `Promise.allSettled` 内のエラーは完全にサイレント。各処理（reply / DB / push）を個別に try-catch し、`console.error` を仕込んでおく

3. **型定義にないパラメータは `// @ts-ignore` を使う**
   - スプレッド構文でのすり抜けは TypeScript はスルーするが実行時に壊れることがある。今後は `// @ts-ignore` か SDK バージョンを上げて解決する

4. **code-reviewer Subagent を PR 前に毎回走らせる**
   - temperature バグのような「TypeScript は通るが実行時に壊れる」問題を事前に発見できる可能性がある

5. **Worktree を最初から使う**
   - 管理画面と Webhook を並行開発できた。次回は機能ごとに branch + worktree を切る

6. **確信度の閾値と「中」の扱いを要件定義に明記する**
   - 今回は最後まで「中」の扱いが曖昧だった。次回は `高/中/低 それぞれのときに何が起きるか` を最初に合意する
